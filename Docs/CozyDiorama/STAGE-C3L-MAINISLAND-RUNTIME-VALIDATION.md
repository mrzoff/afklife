# Stage C-3L — MainIsland Runtime Validation (часть 1: Unity Editor Play Mode)

Статус: **Editor-этап пройден. Android-этап НЕ начат.** `useContinuousPathNetworkRenderer` по умолчанию остаётся `false`.
Ветка: `feature/cozy-diorama-stage-c3l-mainisland-runtime-validation` (локально, без push).

## Что проверялось

Реальный `MainIsland` в Play Mode (`D:\afk\AFKIsland-c3e`), реальная копия Save v8 и 4 выращенных сейва (C-3J, 12 сессий).
Флаг включался только на время теста (`vis.UseContinuousPathNetworkRenderer`). Реальный сейв подменялся и после каждого запуска
восстанавливался побайтно (`D:\afk\c3l-run.ps1`, SHA `E933BA50…13401` совпадал после каждого запуска).

Сценарии (`CozyDioramaStageC3LRuntimeProbe`, `-l3Scenario`):
| сценарий | сейв | результат |
|---|---|---|
| `real` | копия реального Save v8 (+ рост 10 сессий в памяти) | PASS |
| `grownreal` | реальный сейв + стартовое засеивание + 12 сессий роста | PASS (4 перекрёстка, 10 узлов) |
| `g101`, `g104`, `g106` | стартовый сейв + 12 сессий роста | PASS |

Проверки на каждом: связность (1 компонента), хижины подключены, 0 складок/переворотов/downward-треугольников,
0 вершин в пруду, швы чанков = 0, учёт мешей (live == created − destroyed), общие материалы, снимок сейва не меняется
при включении, OFF→ON→OFF ×3 (количество Mesh и GameObject возвращается к baseline, хэши мешей идентичны во всех циклах),
инкрементальный результат == свежая полная перестройка, совпадение двери хижины на плане и в модели.

## Находки (то, что verifier не показывал)

Runtime-проверка нашла четыре дефекта, которые метрический verifier K пропускал. Все исправлены, verifier расширен.

1. **Покрытие verifier'а по yaw хижин было неполным.** Реальные хижины стоят под произвольным yaw; в verifier не было
   развёртки двери хижины относительно дороги (добавлена секция A2: 7 базовых раскладок × yaw × 2 варианта хижины + реальный сейв).
   До исправления: `cases=2870 clean=2600 dirty=270, flipsRibbon=192, flipsJunction=98`
   (`verifier-hut-sweep-BEFORE-fix-report.txt`).
2. **Переворот ленты на свободном конце хижинной ветки** (`SettlementPathMeshBuilder`): ширина «пригвождалась» к полной
   на свободном конце за крутым изгибом. Теперь `pin` только у концов, присоединённых к перекрёстку (`startTrim/endTrim > 0.001`);
   у свободных концов допускается сужение, `EmitEndCap` использует асимметричные радиусы.
3. **Переворот веера перекрёстка** на косых T-перекрёстках хижинных ветвей: пересекающиеся соседние рёбра на радиусе хаба.
   Добавлен тест пересечения (`la × rb < 2e-4` при секторе < π) — обе вершины кольца пропускаются.
4. **Баг интеграции (визуальная коррекция двери хижины не применялась).**
   `HomeSettlementVisualizer.ClearChildren` вызывает отложенный `Destroy`; при смене сигнатуры чанка (ровно переход OFF→ON)
   старая хижина `Hut_N` ещё жила рядом с новой, и `Transform.Find("Hut_N")` в блоке коррекции находил **старую**, умирающую хижину.
   Коррекция поворота уходила в никуда, дорога не доходила до видимой двери (зазор 0.79 m). Исправление — 3 строки:
   дети отсоединяются (`SetParent(null)`) перед `Destroy`. Это исправление существующей коррекции, не новое исключение для хижин.
   После исправления: `planDoor-vs-model = 0.00 m`, ближайшая вершина дороги к видимой двери 0.06 m.

## Результаты после исправлений

- Verifier K final: `cases=2870 clean=2870 dirty=0`, foldbacks=0, flips 0/0/0, downward=0, `steepNonSliverTriangles=0`,
  стоимость построения 1.06× от legacy (`verifier-final-after-fix-report.txt`).
- Регрессии (batch): C-3E, C-3F, C-3G (15/15), C-3I, C-3J — PASS. Артефакты, которые они перегенерируют
  (защищённая сцена C3E, материалы, старые скриншоты, ProjectSettings), откатываются `git checkout`.
- Игровые сценарии: `foldbacks=0 flips=0/0/0 downward=0`, `minUpDot` 0.93, рельеф до 20.9° (холмистый), швы 0.
- **Сужение:** игровые сценарии — минимальный `widthRatioMin` 0.72–0.79, ни одного участка уже 70 % (0/118…0/163).
  Verifier (худшие искусственные случаи крюка хижины): minWidthRatio 0.569, 0.6 % выборок уже 70 %, только у свободных концов хижинных ветвей.
  Ограничитель внутреннего края не ослаблялся.
- Время (Editor Mono, JIT включён): первый `RebuildFromSave` с ON 86–162 ms (включает JIT), последующие 14–48 ms;
  инкрементальный пересбор 17–50 ms на сессию роста. Это время всего `RebuildFromSave`, не только Apply; замер на устройстве — в Android-этапе.
- Утечек мешей нет: после каждого OFF живых owned-мешей 0, `created == destroyed`.

## Два особо отмеченных места

- **Прямой угол за один шаг:** в игре реально встречается поворот до 78° за шаг 0.12 m (радиус 0.08–0.16 m) на ветке хижины
  (`sharpturn0` в `grownreal`/`g101`/`g104`/`g106`); визуально дорога без складок и разрывов. Строго 90° за шаг естественный рост C-3J не создаёт —
  такой случай проверяется только искусственно в verifier.
- **Острый перекрёсток:** в игре минимальный сектор перекрёстка 78–86° (C-3J не создаёт острее). Визуально перекрёстки целы;
  у V-образных развилок между рукавами остаётся узкая прорезь (видна в `c3l-grownreal-07`). Перекрёстки <60° проверены только verifier'ом.

## Наблюдения (не дефекты геометрии)

- Плиты `Clearing_Pad` (тёмно-коричневые квадраты) поверх дороги прерывают её визуально в ряде мест. При OFF они скрыты залитым
  коричневым legacy-полом. Это раскладка/размер плит, не renderer; стоит обсудить отдельно.
- Реальный сейв при первом запуске не содержит settlement-масок — стартовое засеивание и первые дороги появляются при загрузке (`ContinueGame`),
  поэтому сценарий `grownreal` сначала вызывает `StarterSettlementSeed.SeedIfEmpty`.
