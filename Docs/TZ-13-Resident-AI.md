# Stage 13 — жители поселения

Подчиняется `Docs/AFK-ISLAND-MASTER-SPEC.md`, раздел 22. Состояние на входе: 0.6.51 / versionCode 81, сейв версии 8.

Статус: **закрыт device-pass'ом на 0.6.56 / versionCode 86**. Пакеты A–D реализованы, editor smoke `ResidentSmoke` зелёный, сейв остаётся версии 8.

Device-pass 0.6.56: установка поверх старого сохранения, `Residents rebuilt: 64 from 64 hut cells, 0 stand on another hut cell` — и на первом запуске, и после `force-stop` + повторного «ПРОДОЛЖИТЬ». HUD после перезапуска: `поселение: расчистки 76 · тропы 145 · камни 3 · дома 64 · жителей 64`. Жители видны на дневном кадре: светлые капсулы стоят на тропах у домов, по одной на хижину. В logcat ошибок нет.

Раздел 6 закрыт так: один житель на хижину, одновременно в движении трое, визуал — капсула-заглушка с подменой на `Resources/AfkIsland/Settlement/Resident_A|B`.

Что оказалось неочевидным при сборке: дом в `HomeSettlementVisualizer` ставится в центр клетки с масштабом 1.28 и шире одной клетки, поэтому житель в центре хижины оказывался внутри постройки и был не виден. Точка стояния вынесена на соседнюю проходимую клетку (`ResidentRoster.FindStandPoint`), маршрут строится от неё же.

## 1. Что уже есть и на что опираемся

- Маска поселения на чанке: 256 клеток, 3 бита, стадии пусто → расчистка → тропа → камень → хижина. Хижина = 4, потолок кодека.
- `SettlementSimulation.SampleSettlementStage(save, worldCellX, worldCellZ)` читает стадию в мировых клетках и работает через границы чанков. Это готовый источник маршрутов, писать новый декодер не нужно.
- `HomeSettlementVisualizer` рисует тропы и дома из маски, картинка стабильна после рестарта (проверено на устройстве 0.6.50).
- `SettlementCellQuery.TryWorldToCell` / `IsHutAtWorldXZ` (0.6.50) переводят мировую точку в клетку и обратно.
- `AnimalSpawner` / `AnimalInstance` — готовый образец: визуал поднимается из сейва, при отсутствии префаба рисуется заглушка.
- Сейв версии 8, `settlementWatermarkUtc`.

## 2. Решения этапа

### 2.1 Жители не пишутся в сейв

Один житель на одну клетку хижины. Идентификатор выводится, а не хранится:

```
res_{chunkX}_{chunkZ}_{cellIndex}
```

Позиция дома — центр этой клетки. Сид облика — `growthSeed` чанка, как у декора.

Почему так: ТЗ 12 прямо запрещает поднимать версию сейва, а список жителей в сейве потребовал бы версии 9 и миграции. Вывод из маски даёт то же поведение бесплатно: нет дублей, нет осиротевших записей, хижина ушла — житель ушёл, после рестарта состав тот же.

### 2.2 Офлайн жителей не считает

Отдельной симуляции жителей нет. В отчёте о возвращении число жителей — производная от числа хижин, а не новая активность. Строки «жители за ночь что-то сделали» не будет: это новая экономика, спекой запрещена.

Прирост поселения за отлучку по-прежнему считает `SettlementSimulation`, её не трогаем.

### 2.3 Runtime — событийная модель, без Update на жителя

Один компонент `ResidentDirector` на сцену:

- тик раз в 3 секунды, не каждый кадр;
- одновременно в движении не больше 3 жителей, остальные стоят у своих домов;
- на тике директор выбирает пару домов и выдаёт задание одному свободному жителю;
- маршрут — BFS по клеткам тропы, камня и хижины, лимит 96 клеток на поиск, результат кешируется по паре (откуда, куда);
- движение — линейная интерполяция по точкам маршрута, скорость 0.7 м/с;
- дошёл — стоит у дома 2–5 секунд, потом свободен;
- пути нет — остаётся у дома и ждёт следующего тика, телепорта не будет.

`Update` у самого жителя нет вообще: позицию двигает директор. Это выполняет ограничение спеки «не создавать сложный постоянный AI Update для каждого жителя».

### 2.4 Визуал — заглушка с подменой на префаб

Отдельного арта жителей в проекте нет. Рисуется заглушка, как fallback у животных: капсула с цветом из палитры поселения. Если в `Resources/AfkIsland/Settlement/` появится `Resident_A` или `Resident_B`, директор подхватит префаб без правки кода.

Анимации в этом пакете нет — только перемещение. Анимация не является источником истины, поэтому её можно добавить позже, не трогая модель.

### 2.5 Что остаётся нетронутым

`SettlementSimulation`, `HomeSettlementVisualizer`, бюджеты 14 / 6 / 2, пороги LOD, формула sway, версия сейва 8. `SoftTint` не двигаем.

## 3. Пакеты

| Пакет | Содержание |
| --- | --- |
| A | `ResidentRoster` — вывод жителей из маски, стабильные id, позиция дома. Smoke: два дома → два жителя, пустая маска → ноль, повторный вызов не дублирует. |
| B | `ResidentPathGraph` — BFS по клеткам тропы, кеш пар, отказ при отсутствии пути. Smoke: два дома и тропа между ними → путь есть; два дома без тропы → пути нет; путь продолжается через границу чанков. |
| C | `ResidentDirector` + `ResidentInstance`, встраивание в `GameBootstrap` рядом с `HomeSettlementVisualizer`. Пересборка на `RebuildFromSave`. |
| D | Строка HUD: к «поселение: расчистки · тропы · камни · дома» добавляется число жителей. |

## 4. Проверки

| Проверка | Ожидание |
| --- | --- |
| Вывод из маски | Одна хижина — один житель. Пустая маска — ноль. |
| Дубли | Повторный вызов `RebuildFromSave` не создаёт второго жителя на тот же дом. |
| Рестарт | После перезапуска состав и точки стояния те же. |
| Маршрут внутри чанка | Дома, соединённые тропой, дают путь. |
| Маршрут через границу | Тропа, переходящая в соседний чанк, продолжается. |
| Нет пути | Житель не двигается, не телепортируется. |
| Офлайн | Число жителей после отлучки равно числу хижин. Симуляция поселения не менялась. |
| Сейв | Версия остаётся 8, старые сохранения грузятся. |
| Нагрузка | Тик директора раз в 3 с, в движении не больше 3. |

### 4.1 Чем закрыто

Все строки таблицы кроме «Рестарт» закрыты editor smoke `ResidentSmoke` (меню `AFK Island/Smoke Residents (Stage 13)`,
прогон в batch mode `-executeMethod AfkIsland.EditorTools.ResidentSmoke.RunBatch`, exit 0 на 0.6.56):

| Блок | Что проверено |
| --- | --- |
| `RunRoster` | Одна хижина — один житель, id `res_{cx}_{cz}_{cell}_{slot}`, пустая маска — ноль, две хижины в разных чанках — двое, id уникальны и отсортированы. Точка стояния на соседней клетке тропы, `y = homeWorld.y + StandHeightOffset`. Блок 3×3 хижин: все девятеро стоят вне построек (кольцевой fallback). Ростер совпадает при повторном вызове и на `SaveClone.DeepClone`. |
| `RunGraph` | Маршрут между хижинами через тропу, начинается и заканчивается на точках стояния. Камень проходим. Тропа через границу чанков даёт точки в обоих чанках. Без тропы маршрута нет, маршрут в собственную хижину отсутствует, несвязанный граф отказывает. Смена маски по `Bind` сбрасывает кеш пары. |
| `RunDirector` | `RebuildFromSave` дважды даёт двоих, лист `_residents` совпадает с `ResidentRoster.Count`, id не дублируются, каждый стартует на `HomeStand`. Убранная хижина уносит своего жителя. `tickSeconds = 3`, `maxMovingResidents = 3`, `moveSpeed = 0.7`. У `ResidentInstance` нет своего `Update`. |
| `RunOfflineAndSave` | Неделя офлайна: число жителей равно числу хижин, `version` остаётся 8, `MigrateIfNeeded` принимает сейв без смены версии, в JSON нет ни `res_`, ни `residentId`. |

Что оказалось неочевидным в самих проверках:

- Клетка-цель проходима в BFS в любом состоянии, поэтому «пути нет» после удаления тропы проверяется только со
  свежепересобранным ростером — иначе точка стояния старой хижины всё ещё лежит на уже несуществующей тропе.
- `Object.Destroy` вне Play Mode удаляет объект только в конце кадра, поэтому «нет дублей» читается из приватного
  списка директора, а не из `FindObjectsByType`.
- `SaveMigrationService.MigrateIfNeeded` возвращает сам сейв при успехе и `null` при отказе — проверка «сейв остался
  версии 8» должна ждать именно `null` на битых данных, а не на валидных.

«Рестарт» закрыт device-pass'ом 0.6.56: после `force-stop` и повторного входа лог даёт тот же
`64 from 64 hut cells, 0 stand on another hut cell`, HUD — `дома 64 · жителей 64`, картинка поселения совпадает.

## 5. Что не делаем

- потребности, голод, наказания за отсутствие игрока;
- экономику и ресурсы внутри AI;
- расписание дня и ночи, сон, работа по часам;
- взаимодействие жителя с игроком;
- прогулки вне клеток поселения;
- постоянный `Update` на каждого жителя;
- новую версию сейва.

## 6. Требует подтверждения

1. Один житель на дом — или дом должен вмещать больше одного?
2. Одновременно в движении три жителя — или другое число?
3. Заглушка-капсула на этом этапе — или этап ждёт арт и не собирается на устройство?
