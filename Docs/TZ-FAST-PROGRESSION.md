# AFK ISLAND — FAST PROGRESSION
## Принципы балансировки офлайн-развития

**Версия:** 1.0  
**Статус:** Предлагается к утверждению  
**Целевой темп:** Быстрое развитие  
**Главная цель:** За первые сутки остров заметно меняется, за 7 дней становится полноценной экосистемой.

---

# 1. Основной принцип

Развитие AFK ISLAND должно ощущаться быстрым, последовательным и естественным.

Игрок не должен ждать несколько дней, чтобы увидеть первые заметные изменения.

При этом быстрое развитие не означает бесконтрольное увеличение количества объектов.

Балансировка должна обеспечивать три результата:

1. Игрок регулярно замечает изменения острова.
2. Разные системы развиваются согласованно.
3. Через неделю остров выглядит значительно богаче, но не перегруженным.

**Главная формула: частые небольшие изменения + регулярные крупные изменения + постепенное усложнение экосистемы.**

# 2. Целевые временные ориентиры

Это целевые состояния мира, а не жёсткие таймеры для отдельных объектов.

| Время отсутствия | Ожидаемое состояние |
|---|---|
| 10–30 минут | Первые небольшие изменения, прогресс роста |
| 1 час | Уже можно заметить развитие отдельных растений и участков |
| 3 часа | Новые растения, заметное изменение растительности |
| 8 часов | Остров визуально отличается от исходного состояния |
| 24 часа | Значительное озеленение, новые животные и первые заметные изменения поселения |
| 3 дня | Хорошо развитая растительность, сформированные участки экосистемы, заметное поселение |
| 7 дней | Полноценная, разнообразная экосистема с природными событиями и развитым поселением |
| 30 дней | Значительно расширенный и разнообразный остров |

Не каждое событие обязано происходить у каждого игрока в указанное время. Это ориентир общего результата при нормальных условиях развития.

# 3. Скорость отдельных систем

Нельзя использовать один общий множитель для всех симуляций.

Каждая система должна иметь собственный темп.

| Система | Приоритет ускорения | Принцип |
|---|---|---|
| Растения | Высокий | Быстрое визуальное озеленение |
| Колонизация растениями | Высокий | Новые участки быстро получают растительность |
| Расширение суши | Средний | Постоянный, но контролируемый рост |
| Животные | Средний–высокий | Появление по мере формирования среды |
| Поселение | Средний–высокий | Раннее появление, постепенное увеличение |
| Погода | Не требует ускорения прогрессии | Атмосферная смена состояний |
| Природные события | Средний | Регулярные интересные изменения без спама |
| Редкие виды | Низкий–средний | Должны сохранять ценность обнаружения |

## 3.1. Растения

Растительность — основной визуальный показатель развития острова.

Игрок должен видеть изменения даже после короткого отсутствия.

Правила:

- первые стадии роста должны проходить быстро;
- молодые растения не должны слишком долго оставаться визуально незаметными;
- кустарники и небольшие растения должны заполнять новые участки;
- большие деревья должны расти медленнее маленьких растений;
- редкие растения должны сохранять особый статус;
- растения не должны погибать из-за отсутствия игрока.

Необходимо разделить:
- скорость роста уже существующего растения;
- вероятность появления нового растения;
- скорость заселения новой территории;
- скорость перехода между визуальными стадиями.

Эти параметры не должны регулироваться одним коэффициентом.

## 3.2. Расширение суши

Суша должна расширяться быстрее, чем в медленной модели, но не должна поглощать весь визуальный мир за несколько дней.

Правила:

- в первый день игрок видит расширение;
- новые участки постепенно получают растительность;
- край острова остаётся естественным;
- скорость расширения зависит от размера доступной территории;
- по мере увеличения острова темп может снижаться;
- не создавать резкие квадратные границы;
- не создавать пустые территории без последующего заселения.

Расширение суши и заселение растений должны быть согласованы по времени.

## 3.3. Животные

Животные должны появляться после формирования подходящей среды.

Правила:

- не заселять неподходящую территорию;
- учитывать доступную землю;
- учитывать условия вида;
- не создавать бесконечный прирост популяции;
- ограничивать количество животных с учётом размера острова;
- сохранять редкие виды редкими.

В первый день игрок должен увидеть первые признаки фауны, а за неделю — заметное разнообразие.

Количество животных должно зависеть не только от прошедшего времени, но и от площади и качества среды.

## 3.4. Поселение

Поселение должно начинать развиваться раньше, чем в текущей медленной модели.

Целевое ощущение:

- первые заметные признаки развития — в течение первых суток;
- несколько заметных изменений — за 1–3 дня;
- сформированное небольшое поселение — примерно за неделю.

Правила:

- дома размещаются на подходящей земле;
- тропы соединяют логически связанные участки;
- поселение не должно появляться на воде;
- здания не должны конфликтовать с растительностью;
- количество построек ограничивается доступной территорией;
- повторная офлайн-симуляция не создаёт дубли.

Не увеличивать только скорость появления домов. Необходимо сохранять логическую последовательность развития поселения.

## 3.5. Природные события

События должны помогать игроку замечать изменения мира.

Правила:

- события должны происходить достаточно часто, чтобы игрок видел результаты;
- одинаковые события не должны повторяться слишком часто;
- редкие события должны сохранять редкость;
- событие должно менять состояние мира, если оно заявлено как значимое;
- Return Report показывает события текущего периода отсутствия;
- нельзя повторно выдавать одно событие как новое без основания.

Не увеличивать частоту событий простым снятием всех ограничений вероятности.

# 4. Принцип последовательного развития

Системы должны развиваться взаимосвязанно.

Пример естественной последовательности:

1. Появляется новая территория.
2. На ней формируются подходящие условия.
3. Появляются растения.
4. Развивается растительный покров.
5. На территорию приходят животные.
6. Появляются условия для развития поселения.
7. Возникают новые возможности и природные события.

Это не обязательная жёсткая цепочка для каждого объекта, а общий принцип организации мира.

Нельзя допускать ситуации, когда поселение растёт быстрее доступной земли или животные появляются там, где нет подходящей среды.

# 5. Нелинейное развитие

Темп должен быть быстрым в начале, но не бесконечно ускоряющимся.

Предлагается три фазы:

### Фаза A — Быстрый старт (0–24 часа)

- высокий темп первых изменений;
- быстрое озеленение;
- первые животные;
- первые изменения поселения;
- заметное расширение острова.

Цель: игрок должен увидеть, что мир действительно живёт самостоятельно.

### Фаза B — Формирование экосистемы (1–7 дней)

- продолжается расширение;
- появляются новые виды;
- формируются участки растительности;
- развивается поселение;
- растёт разнообразие событий.

Цель: остров приобретает узнаваемый облик.

### Фаза C — Долгосрочное развитие (7–30 дней и далее)

- рост становится более зависимым от доступной территории;
- редкие виды появляются по особым условиям;
- новые участки получают собственную экологическую структуру;
- поселение развивается постепенно;
- разнообразие важнее простого увеличения количества объектов.

Цель: игрок продолжает получать новые открытия, а мир не превращается в бесконтрольную массу объектов.

# 6. Ограничения и защита от перенасыщения

Быстрая прогрессия не должна приводить к следующим проблемам:

- слишком много деревьев на единицу площади;
- чрезмерная плотность кустарников;
- животные занимают всю доступную землю;
- дома появляются вплотную друг к другу;
- тропы перекрывают растительность;
- остров слишком быстро увеличивается;
- водоёмы зарастают;
- редкие виды перестают быть редкими;
- визуальная производительность резко падает.

Для каждой системы определить:

- минимальный интервал появления;
- максимальную плотность;
- ограничение количества на площадь;
- условия появления;
- условия размещения;
- зависимость от размера мира.

Лимиты должны ограничивать перенасыщение, а не искусственно останавливать нормальный прогресс.

# 7. Офлайн-симуляция

Быстрое развитие должно корректно работать независимо от продолжительности отсутствия.

Обязательные сценарии тестирования:

| Отсутствие | Что проверяем |
|---|---|
| 1 час | Небольшие изменения |
| 3 часа | Первые заметные результаты |
| 8 часов | Видимое развитие |
| 24 часа | Значительное развитие |
| 72 часа | Сформированная экосистема |
| 168 часов | Полноценный живой остров |
| 30 дней | Отсутствие переполнения и разрушения баланса |

Правила:

- не вводить искусственный лимит в 24 часа;
- не обрезать длительное отсутствие без обоснования;
- не рассчитывать каждую секунду отсутствия отдельным циклом;
- использовать существующие механизмы временных интервалов;
- не применять один и тот же период дважды;
- сохранять watermark;
- не терять прогресс при ошибке записи;
- не изменять авторитетное состояние до успешного commit.

# 8. Техническая реализация балансировки

Перед изменениями необходимо провести аудит текущих параметров.

Для каждой системы составить таблицу:

| Параметр | Текущее значение | Целевое значение | Источник |
|---|---:|---:|---|
| Время роста растения | Измерить | Определить | PlantData / Simulation |
| Частота колонизации | Измерить | Определить | PlantColonization |
| Расширение суши | Измерить | Определить | WorldGrowthSimulation |
| Частота появления животных | Измерить | Определить | FaunaSimulation |
| Плотность животных | Измерить | Определить | Fauna / AnimalSpawner |
| Частота развития поселения | Измерить | Определить | SettlementSimulation |
| Частота событий | Измерить | Определить | WorldEventsSimulation |

### Основное техническое требование

Параметры баланса должны быть централизованы там, где это соответствует существующей архитектуре.

Предпочтительно использовать существующие ScriptableObjects и конфигурационные данные.

Не создавать глобальный ProgressionManager только ради изменения нескольких коэффициентов.

Не дублировать параметры в нескольких независимых местах.

# 9. Метрики балансировки

Для каждого тестового периода фиксировать:

- количество новых клеток земли;
- общую площадь доступной суши;
- количество новых растений;
- количество выросших растений;
- количество животных;
- количество новых животных;
- количество домов;
- количество троп;
- количество событий;
- количество редких открытий;
- плотность объектов;
- время расчёта симуляции;
- размер сохранения.

Важно сравнивать не только абсолютные количества, но и плотность объектов на единицу площади.

Например, увеличение количества деревьев само по себе не является хорошим результатом, если площадь острова увеличилась ещё быстрее и визуально он остался пустым.

# 10. Тестирование баланса

Для каждого сценария:

1. Создать одинаковое исходное сохранение.
2. Выполнить офлайн-симуляцию на заданный интервал.
3. Зафиксировать результат.
4. Повторить симуляцию на том же исходном сохранении.
5. Сравнить результаты.
6. Проверить отсутствие случайных дублей и ошибок.
7. Проверить сохранение и повторную загрузку.

Сравнить минимум два сценария:

- быстрый последовательный вход: 8 раз по 1 часу;
- один длительный вход: 8 часов.

Результат должен быть близким по суммарному прогрессу. Допустимые различия из-за дискретных событий и округления нужно определить отдельно.

Также сравнить 24 часа, 72 часа и 168 часов.

# 11. Что запрещено менять без отдельного контракта

- SaveService;
- SaveMigrationService;
- формат Save v8;
- WorldGrowthService transaction flow;
- систему watermark;
- постоянные ID растений и животных;
- механику восстановления старых объектов;
- архитектуру Chunk;
- существующую систему воды;
- канонический CollectionService.

Не менять визуальные ассеты только ради ускорения симуляции.

Не добавлять новые валюты, ежедневные награды, энергию, stamina, bait и обязательные задания.

# 12. Критерии приёмки Fast Progression

Этап принимается, если:

1. За первые 24 часа остров визуально заметно меняется.
2. За 3 дня формируется выраженная экосистема.
3. За 7 дней остров выглядит полноценным живым миром.
4. Растения, животные и поселение развиваются согласованно.
5. Остров не перенасыщается объектами.
6. Редкие виды и события сохраняют ценность.
7. Длительное отсутствие не ограничивает прогресс искусственно.
8. Повторный запуск не начисляет прогресс дважды.
9. Save v8 остаётся совместимым, если изменение не требует отдельной миграции.
10. Нет регрессий в рыбалке, коллекции, событиях и поселении.
11. Время расчёта симуляции остаётся приемлемым для мобильных устройств.

# 14. Итоговое решение

AFK ISLAND переходит на модель Fast Progression.

Основные целевые результаты:

- первые изменения — в течение минут;
- заметное развитие — в течение первых часов;
- существенное преображение — за первые сутки;
- сформированная экосистема — за неделю;
- долгосрочное разнообразие — после первой недели.

Главное правило:

**Игрок должен регулярно видеть, что остров развивается, но никогда не должен чувствовать, что развитие превратилось в неконтролируемое накопление объектов.**
